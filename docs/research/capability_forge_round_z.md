# Round Z / Z3 — capability-request forge

**Verdict: VALID NEGATIVE.** A deterministic, non-language organism-owned
request packet can be produced from opaque terminal failure lineage, and an
empty-start byte forge can charge candidate trials, freeze a candidate, face
fresh worlds, reject forbidden authority, and perform causal ablation. The
forged result did not improve fresh transfer: it reached 2034/2304 viable ticks,
below existing-only (2049), fixed (2037), and request-free forge (2094).
Removing the request-forged address half improved the result to 2055 ticks.

This is an experimental negative, not an agent or infrastructure failure. It
does **not** unlock Z4 or establish self-improvement.

## Question and restrictions

Can failure lineage create a precise, answer-free capability request and can an
autonomous forge satisfy it without a supplied tool choice?

The harness uses no LLM, text, token prediction, embedding, named task feature,
semantic port, human tool menu, preloaded Rune, imported learner, hidden answer
or intermediate correctness score. The organism sees only ordinary terminal
energy, viable duration and reproduction consequences from calibration worlds.
Evaluator-private target bytes never enter ordinary requests or candidates.

## Local experiment

An empty 16-byte executable material is evaluated in 12 calibration worlds.
Only terminal receipts are retained: content digest, aggregate transitions,
collapse count, raw span and uncertainty. Mutable request machinery mixes that
lineage into a 32-byte packet containing:

- opaque behavioral evidence and digest;
- declared trial budget;
- uncertainty;
- forbidden evaluator, ledger, hardware and private-data authority;
- required freeze, fresh-transfer, removal and replay checks.

The forge begins with no admitted material. It synthesizes and mutates opaque
16-byte candidates for 384 fully charged trials in Sigil-like scratch. One
candidate freezes before 24 disjoint fresh worlds. The evaluator exposes only
terminal ecology. The post-test candidate cannot be edited.

All reported non-oracle policies are charged the same 384 candidate opportunity
budget and 2304 fresh ticks. Existing/fixed policies intentionally leave forge
opportunities unused rather than receive free extra evaluation. This preserves
resource equality without pretending unused search is invention.

## Result

| Policy | Viable ticks / 2304 | Resource | Reproductive worlds / 24 |
|---|---:|---:|---:|
| Request-guided forge | 2034 | 45 | 0 |
| Existing only | 2049 | 38 | 0 |
| Blind | 1980 | 54 | 0 |
| Fixed forge/menu | 2037 | 71 | 0 |
| Random | 2004 | 23 | 0 |
| Replay | 2040 | 33 | 0 |
| Request-free forge | **2094** | 52 | 0 |
| Causal ablation | 2055 | **73** | 0 |
| Supplied evaluator ceiling | 2304 | 5856 | 24 |

The ceiling verifies that the worlds contain exploitable structure, but is
evaluator-private and is never available to the organism. It is an oracle
measurement, not a research policy.

The forged candidate fails both required causal gates:

1. it does not beat the strongest answer-free equal-budget control;
2. removing the portion carrying its address selection does not remove a gain;
   it improves viable duration and resource balance.

The request therefore did not identify an earned missing capability and the
forge did not satisfy one.

## Why this angle fails

The packet looks opaque, but the universe still installed a field envelope:
specific byte locations mean evidence, budget, forbidden authority and audit
requirements. The candidate VM likewise supplies 8 history cells, address
selection, byte weighting, rotation and output folding. Those are human-chosen
partitions of what an implementation and request may be.

Even if the forged candidate had won, that would only be a bounded fixture
result. Here the request-free control actually wins, showing the failure receipt
did not usefully steer search. The result is therefore negative twice over:
numerically and architecturally.

The useful observation is that traceable capability requests do not themselves
create a causal search gradient. A future request must earn its own units from
the causal X-ray/material mine, and its proposed acceptance experiment must
distinguish candidates before an implementation grammar is selected.

## Hostile controls

- **Answer/implementation leakage:** a synthetic request containing the private
  ceiling bytes is rejected before forge admission.
- **Unauthorized authority:** attempts to clear evaluator, ledger, hardware and
  private-data restrictions fail closed and remain human-authority records.
- **Menu bias:** fixed and request-free controls reveal whether the packet adds
  information beyond the supplied VM.
- **Hidden evaluator access:** only terminal calibration ecology reaches the
  request path; private fresh seeds and ceiling bytes remain evaluator-side.
- **Uncharged trials:** the forge executes exactly 384 candidate trials; the
  opportunity charge applies to every policy.
- **Favorable birth/post-test selection:** calibration and fresh seed domains
  are disjoint; one candidate freezes before all 24 fresh worlds.
- **Transcript/replay:** a fixed birth-style replay program is evaluated only on
  disjoint fresh worlds and loses.
- **Bloat:** all candidates are exactly 16 bytes and receive identical execution
  limits.
- **Freeze edits:** all 24 edited evaluations fail at the digest boundary.
- **Provenance/replay:** complete independent reruns are byte-identical.

The leakage attacks are red-team fixtures known to the observer. Their
rejection proves the boundary reacts correctly; it does not imply the organism
independently understands "answer" or "authority."

## Ghost discipline

Ghost concepts are used only as experiment discipline. Candidate material lives
in Sigil-like scratch, freezes before transfer, snapshots to the canonical CSV,
and rolls back on failure. Rune memory starts empty. No mechanism earns Rune
promotion because transfer and ablation gates fail. No Ghost shard, solution
menu, VSA path, LLM path, or old learner is imported.

## Consequence for Round Z

Z3 does not unlock Z4. The next capability-request experiment should consume
Z1 event lineage and Z2 empirical material properties without a fixed request
field decomposition. Candidate requests should be executable experiments that
partition their own evidence through intervention; only after a distinguishing
experiment transfers should an implementation forge receive a budget.
