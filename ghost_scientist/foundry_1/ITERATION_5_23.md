# Foundry readiness iteration 5.23

This iteration closes two different kinds of uncertainty without inflating
readiness.

Phase 135 refreshes the defining EggMind record. The paper publishes real
technical substance: EqSatL, the agent roles, three evaluator budget classes,
proof-derived semantic-tag motifs, the dependency-risk equation, hinted
simplification, the default model, aggregate model usage, and online resource
limits. It does not publish an executable source revision or sixteen
outcome-determining details needed to reproduce the reported system, including
the prompts and action policy, numerical evaluator budgets and promotions,
proof-region extraction, tag mapping, motif cache policy, dependency weights,
EqSatL-to-egglog execution, exact workload fixtures, or final synthesized
strategies.

The result is a current specification no-go, not a permanent impossibility
claim and not a criticism of the reported system. The partial adapted parser
remains valid, but it is not EggMind and cannot satisfy A8. A deterministic
LLM-free system based on the prose would be a new adapted control with its own
name and falsification criteria.

Phase 136 then advances the shortest remaining source-faithful route without
inventing source. A pre-frozen exact-artifact ingress gate loads all 310
registry identities from ISAMORE's pinned Cargo.lock. It requires exact
name/version filenames and registry SHA-256 checksums, validates the archive
root and manifest, rejects links and unsafe paths, and publishes a batch only
after every member passes. A synthetic exact archive stages successfully.
Eleven hostile cases are rejected, including checksum mismatch, malformed
archives, traversal, links, duplicates, missing manifests, unknown identities,
and preexisting destinations.

The synthetic archive tests the gate only. The real ingress inbox is empty, so
zero upstream artifacts were acquired. P1 remains `3/4`, readiness remains
`5/6`, production integration remains `6/10`, and validation-v6 remains
sealed. When exact transport returns, the new gate removes version-editing and
source-substitution decisions from archive staging; the unchanged ISAMORE
build still additionally requires native Coin-OR CBC and the pinned nightly.
