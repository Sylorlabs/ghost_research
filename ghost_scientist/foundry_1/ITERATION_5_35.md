# Foundry readiness iteration 5.35

The local remediation moved beyond permissive template binding.

Phase163 froze a new five-fold hash split before prediction outcomes. For each
fold, the learner saw only the other four folds and selected the most frequent
complete operator sequence for each sufficiently recurring cross-family
topology. It made 18 exact heldout predictions across eleven families and all
five folds on 279 eligible motifs. Boundary-frequency and size-frequency
controls made zero exact predictions. Two independent implementations produced
byte-identical ledgers and rejected all 16 hostile cases twice.

Phase164 then required the complete canonical body rather than operator names:
all operators, argument recipes, input and output tensor types, and output
boundaries had to be chosen from training before heldout access. Seventeen
complete bodies were predicted byte-identically across ten heldout families
and four folds, versus four exact bodies for each frequency control. These are
three unique concrete exact tool candidates.

Phase165 executed every match on runtime tensor values captured from its
authenticated heldout graph. The generic candidate interpreter and an
independently written explicit stock-ATen executor both passed all 17 rows and
all 17 declared outputs at the frozen tolerance. Removing the three-body
library reduced the exact match count from 17 to zero, with exact per-body
losses.

All three unique bodies compiled through candidate and stock-composition
routes. Their normalized Inductor code digests were identical in every case.
The result is therefore executable exact tool reuse and a valid native
duplicate, not a runtime invention.

This is genuine progress toward autonomous construction, but the unresolved
scientific endpoint remains total utility. No whole-graph replacement or lower
total cost has been shown, and the machine reproduced known stock semantics.

validation-v7 payload or prospective execution.
